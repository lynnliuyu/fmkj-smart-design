## 目标与范围

点位按设备类型及参数找到兼容的具体 SKU，用户确认后用于图标、报价和采购；产品库或报价反向生成点位时使用同一套规则。位置规划可以先于产品选型完成。

字段、版本、兼容性与历史数据合同以 [产品库与点位映射整理方案](../docs/product-point-mapping-plan.md) 为准；词汇以 [CONTEXT.md](../CONTEXT.md) 为准。本文只管理执行顺序和完成条件。

本轮交付包括结构化选型、配套用料和报价闭环的业务实现，以及产品整理工具。正式客户方案仍由用户微调；合成产品与破坏性验证使用隔离数据，产品整理以最新数据库数据及差异集为准。厂商参数与供货价格需要实际依据；本轮未重新识别全部客户图纸，也未接入实时供应商接口或进行部署。

## 已确定的规则

- 产品系列、具体规格、设备类型和图标分别表达；系列不直接作为精确采购规格。
- 一台实物按一台计数。按键数、继电器路数、灯组和场景数独立。
- 布局确认和选型核验独立；正式选用、待评估、预留分别处理。
- 参数未知返回“资料不足”，类型或参数冲突返回原因；产品关联需要明确选择，不自动持久化第一条关键词命中结果。
- 旧产品、点位、楼层与场景身份保持稳定；旧确认版、报价与金额不通过整理任务改写。
- 方案 v3、助手草稿 v2 兼容读取旧格式；CAD v1 坐标回传保留选型字段。
- 每点位一个主产品，配套用料独立记录产品、角色、数量与单位；窗帘电机、轨道和配件已接通展开，其他组合可通过同一清单表达。

### 020.1 关闭错误的隐式关联

涉及：`components/projects/point-map-workbench.tsx`、`lib/point-map-plan.ts`、`lib/point-icons.ts` 及对应测试。

- 手工新增图标不再直接绑定第一条文本匹配产品；尚无合格具体规格时保留空 productId。
- 关键词只用于候选检索，不能作为已选型依据；历史错误关联显示问题而非自动换成另一产品。
- 产品反向入点位时，未核实系列不伪装成已选具体型号；缺少明确类型或实体规格时要求先在产品后台补齐资料。
- 固定合成案例：AP 与 APP；无线 AC 与空调；1～4 键价格列表；“支持控制空调”的屏幕；PoE 摄像头与交换机；四寸屏与普通面板。

完成条件：新建 AP 和四寸屏不会关联普通开关；键数列表不被解释为已确定四键；用户已有坐标、ID、备注、场景及关联不被静默改写；布局与数据库保存继续可用。

### 020.2 建立产品与类型合同

涉及：`lib/device-types.ts`、`lib/product-selection.ts`、增量 SQL；以及 `scripts/run-migration.mjs`、`lib/product-admin-service.ts`、产品 API、管理页、产品库、fallback 和导入脚本。

- 按合同新增类型字典、系列/具体规格身份、结构化参数、协议、能力、参数核验、价格核验和 mappingRevision。
- 首先覆盖开关、场景/调光控制、屏幕、网关、无线网络、室外摄像头和窗帘；其他现有类别保留可读，未映射类型进入待整理。
- 旧产品默认 legacy / pending，保留价格原值及原描述。SKU 子项与系列父项检查类型及引用，禁止循环。
- 明确类型参数允许值、单位和比较方式；前后端复用同一语义校验。新增类型或协议使用稳定键，避免以中文展示名作为数据库关联键。
- 所有产品读写及 DTO 转换保留结构化字段；导入路径遵守同样规则，重新导入不会抹掉人工核验或把资料缺失变成 verified。
- 在产品整理之前补齐 quote_items 的版本化 product_snapshot 和读取逻辑：旧行缺失的类别、图片、规格等按整理前实际展示结果冻结，标记 legacy 来源和采集时间；已有报价值与金额保留，无法恢复的原始资料不猜填。
- 增量迁移在空库和现有合成库可执行、可重复；实施前验证与当前类别/平台归一化迁移的兼容性，避免后续重跑覆盖已核实数据。

完成条件：不同键数和接线规格可以保存为不同具体 SKU；系列可展示但不作为精确采购候选；非法参数和无依据 verified 被服务端拒绝；产品到报价再到点位的字段不丢失；旧报价已具备独立于产品变更的展示保护。

### 020.3 整理产品数据与审核入口

涉及：产品后台、`scripts/review-product-mapping.mjs`、现有导入脚本；沿用现有操作日志与管理权限。

- 为“待整理、具体规格、系列、参数冲突、价格待核”提供筛选及逐条审核；字段按设备类型显示。
- 将本次 49 条审核候选作为待核线索，实施时重新读取最新产品，不把本机快照当作最新真值。
- 优先处理开关与中控的键数、继电器路数、接线、尺寸及角色；再处理窗帘成套范围、网络与室外监控缺项、灯具与驱动类型及串行资料。
- 混合规格记录保留原 ID，明确标系列或 legacy，只创建已核实存在的子 SKU。保留来源和人工判断，冲突资料不能凭价格相同合并。
- 整理工具默认 dry-run，输出字段差异、证据、受影响点位/报价、预期 revision 和更新数量；应用经过事务、并发检查和日志，可重复执行且不重复创建。
- 应用前备份并在隔离库验证恢复；回滚按本次变更 ID 及预期版本恢复，遇到后续人工更新则报告冲突，避免覆盖。
- 应用产品资料变更前检查受影响报价的展示快照已经存在；缺快照时先冻结整理前展示结果，不能先改产品再补，以免丢失回退资料。

完成条件：每条候选都有明确的处理状态与原因；审核前后 ID/原始资料及引用可追溯；无依据的项继续待核；产品整理不自动替换客户点位或重算既有报价。

### 020.4 接通点位要求与统一选型

涉及：`lib/point-map-plan.ts`、`lib/point-map-design.ts`、`lib/point-map-service.ts`、点位 API/client、点位编辑/渲染、产品及报价入点位入口、CAD 往返与本地缓存。

- 按合同实现方案 schemaVersion 3 与助手草稿 version 2；旧格式兼容读取，明确拒绝未来版本。
- 点位编辑先展示类型、要求、选用状态，再展示兼容候选及缺项。按键、继电器路数、场景用途分别编辑；未知键数不会默认写入 1。
- 兼容判定返回 compatible / incomplete / incompatible 和字段原因；产品入点位与点位找产品使用同一规则。
- 自动建议先预览；用户确认具体 SKU 后由服务端重验并生成 selection 快照。绕过 UI 提交的伪造核验、错型号或冲突必须被拦截为有效选型，普通草稿仍可保留问题以继续设计。
- 设备类型或关键要求改变后重新选型及设计复核；图标纯样式更新保留关联。位置拖动继续沿用现有精度和复核规则。
- 当前缺选用状态的旧点位在升级视图中进入 proposed，保留旧关联及诊断；用户保存才更新草稿。历史确认版保持只读，缺新快照时明确标旧版资料。
- 结构化选型数据经过保存、加载、助手导入导出、本地备份和 CAD 位置回传完整保留；相同 ID 再导入继续保留人工微调。

完成条件：用户能在原位置选择三键或四寸屏，再选择符合要求的具体型号；刷新与再次导入后数据完整。无产品可用时可保存和确认布局，并明确显示待选型。原有权限、只读与 revision 冲突检查仍有效。

### 020.5 接通报价与历史快照

涉及：`lib/quote-draft.ts`、`lib/quote-authoring.ts`、`lib/quote-point-map-command.ts`、`lib/quote-save.ts`、报价 API/UI、确认版本持久化和增量 SQL。

- 点位报价来源保存设计 revision、具体产品 mappingRevision 及选型快照；类型定义版本由共用字典管理，确认图固定图例版本。正式同步在服务端读取最新数据校验，旧 localStorage 缓存不成为可信采购依据。
- 正式选用设备必须定位、设计确认、具体 SKU 有效、参数兼容；价格待核与已核零价分别表示，正式采购金额需要依据或人工确认。
- 同步先预览增减、产品/规格变化及阻断项；有阻断缺项时保留旧条目。明确的删除/取消选用在预览后正常移除，不能把失败过滤为空解释成全量清空。
- 按实体点计数、按产品与楼层房间分组，保留 pointIds 来源；重复同步不叠加，手动来源和其他项目条目继续保留。人工单价、成本或折扣有差异时提供变更比较，避免重新拉取目录价静默覆盖。
- 点位确认快照冻结类型、规格及图例；报价另冻结 SKU、单位、规格、类别/图示和来源版本，报价行保留金额与折扣。价格依据在采购预览时校验。旧报价读取已有快照和 020.2 冻结的 legacy 展示资料，产品改名、改规格、下架不改变历史结果。
- 报价到点位只支持可按实体数量展开的设备。米、配件、服务等条目保持报价数量，不经整数四舍五入生成一串设备点。

完成条件：已确认三键设备采购数量为 1；预留 AP 不计采购；错配或过期规格不能绕过服务端计价；连续同步数量稳定；下架/修改产品后旧图和报价仍可复现；没有阻断问题的最新来源才能更新本项目点位来源报价。

### 020.6 扩展配套用料

- 一个窗帘安装点可对应电机、轨道长度、传动头和安装材料，保持现有轨道＋电机合并图示。
- 主设备与配件使用独立用料身份，数量包含单位和计量依据。米数支持小数，未知长度保留待测，不默认 1 米。
- 配套模板记录必配/选配及实际包含范围；套装已包含的部件不再另加。两处安装使用相同 SKU 时不因全局去重而少算。
- AC＋PoE 一体设备按实体身份计 1 台，多个能力/逻辑角色不重复采购；不同实物仍分别计数。

完成条件：合成窗帘点可展开主设备、实测米数和配件；重复展开不叠加；缺长度/必配型号时采购清单明确未完成；一体网络设备与多处同款设备均正确计数。

## 核心验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| AP 图标遇到开关描述中的 APP | 无类型匹配，不关联 |
| 开关描述列出 1/2/3/4 键价格 | 系列或资料不足，不确定键数 |
| 三键、两路负载的合成产品 | 按键与继电器要求分别比较，数量仍为 1 |
| 四寸屏支持空调及窗帘控制 | 保持屏幕类型，不转空调/窗帘设备 |
| 三键要求遇到单键、接线不符或未知产品 | 分别显示冲突或资料不足，不能作为合格选型 |
| 无 SKU 的已核布局 | 可保存/确认布局，采购显示待选型 |
| 预留/待评估 AP | 保留图上位置，不直接产生采购数量 |
| 旧草稿→新保存→导出导入→CAD 回传 | 身份、精确坐标、要求、绑定、复核信息完整 |
| 修改已选产品规格或停用产品 | 草稿提示重新核验，旧确认图与报价保持原样 |
| 旧报价规格为空、类别/图片原本实时取产品 | 在整理前冻结实际展示，整理后仍可复现；缺失历史信息标 legacy |
| 客户端伪造兼容/数量/来源版本 | 服务端拒绝有效选型或报价更新，旧数据保持 |
| 目录审核通过但参数/价格待核 | 不自动变成已完成采购选型 |
| 读取产品失败或全量候选过滤为空 | 报告问题，保留已有报价 |
| 正常取消选用/删除点位并确认同步差异 | 移除对应点位来源行，保留手工行 |
| 轨道 3.6 米或配件进入报价 | 数量与单位保留，不生成 4 个实体点 |
| 同 SKU 两处窗帘 / AC＋PoE 一体机 | 前者分别计用料，后者一台实物只计一次 |
