# 计划 029：概览移入侧边栏，顶部栏按项目上下文切换

Status: DONE
Started: 2026-10-21
Completed: 2026-10-21

## 目标

精简顶部栏入口，并让顶部栏记住用户当前正在处理的项目：进入某个项目后，切换「方案报价」直接落到该项目的方案报价页面，不再回到报价列表重新选项目。

## 用户决定（2026-10-21 本轮聊天）

| 问题 | 用户决定 | 本轮落实 |
| --- | --- | --- |
| 概览入口位置 | 从顶部栏移到侧边栏 | 侧边栏「常用」新增「概览」→ `/`；原来的「项目」从 `/` 改指项目列表 `/projects` |
| 顶部栏「方案报价」点进去的目标 | `/projects/<id>?tab=solution-quote`（项目工作台的方案报价页） | 项目内直接带上项目 ID，不再出现「报价列表」让用户重新选择 |
| 顶部栏显示范围 | 点位设计页也显示，并沿用当前项目 | `/point-map` 也显示顶部栏；从 `projectId` 查询参数还原项目上下文 |

## 实现

- 新增 `lib/workbench-nav.ts`：纯函数解析顶部栏模型。
  - `readWorkbenchProjectId(pathname, search)`：项目详情路径优先，其次读取 `projectId` 查询参数。
  - `buildWorkbenchNav(pathname, search)`：固定输出「项目 / 方案报价 / 合同」三项；项目内指向 `/projects/<id>` 及其 `?tab=solution-quote`、`?tab=contract`，项目外保持 `/projects`、`/quotes`、`/contracts`。
  - `showsWorkbenchNav(pathname)`：概览、项目、报价、合同、点位设计页显示顶部栏。
- `components/site-header.tsx`：顶部栏不再包含「概览」；改用上面的模型渲染桌面导航与移动端下拉菜单，并给当前入口加 `aria-current="page"`。读取查询参数的部分包在 `Suspense` 中，静态预渲染页面保持可构建。
- `components/app-sidebar.tsx`：侧边栏新增「概览」；「项目」改指 `/projects`。
- `tests/workbench-nav.test.ts`：9 项覆盖项目内/项目外链接、标签高亮、点位设计上下文、ID 编码往返与顶部栏显隐范围。

高亮规则：`/point-map` 与 `/quotes` 都算「方案报价」工作流（延续 ADR 0007 把点位设计与报价单视为一条连续流程）。项目工作台里执行与资料类次要标签（工单、交付、售后、成员、现场图片）仍归属「项目」入口。

## 不改变

- ADR 0007 的三个连续入口「点位设计 / 报价单 / 客户交付」及其直达地址不变；项目工作台方案报价页仍提供「打开草稿继续核对」「快速报价」「查看报价版本」。
- `/quotes?projectId=` 报价编辑页、`/point-map?projectId=` 点位工作台、项目换型与报价联动规则均未改动。
- `/contracts` 目前不读取 `projectId`，所以项目内的「合同」指向项目工作台的合同标签页；合同列表仍由该页「查看合同」直达。真正按项目过滤合同需要另开计划。

## 第二轮（2026-10-21）：去掉项目工作台里重复的段落入口

顶部栏已经成为项目段落入口后，页内再放一套「资料 / 方案报价」标签属于重复入口，本轮删掉：

- `components/projects/project-workspace.tsx`：不再渲染 `TabsList` 与 Tabs 触发器，改成按当前段落直接渲染内容。顶部栏负责「项目（资料）/ 方案报价 / 合同」，页内只保留一个「执行与资料」下拉，收「工单 / 交付 / 售后 / 成员 / 现场图片」五项（合同段已由顶部栏承担，不再在下拉里重复）。
- 「执行与资料」下拉移到项目指挥台卡片的操作区，和「继续方案报价」「返回项目列表」并列，页面少一行空标签栏；下拉里当前段落带勾选标记。
- 段落选择写回地址（`router.replace(..., { scroll: false })`）：刷新或从顶部栏切回主入口时仍落在同一段，也避免「页内切到工单后再点顶部栏项目却不动」的状态不一致。
- `lib/workbench-nav.ts` 导出 `WORKBENCH_BASIC_TAB` 与 `isWorkbenchPrimaryTab`，让顶部栏承担的主入口与页内下拉共用同一套取值，避免两处各写一份。

未改动：`/projects/<id>?tab=<段>` 的直达地址、`point-map`/`quote`/`workOrder` 旧参数的兼容映射、各段落内容本身。

## 第三轮（2026-10-21）：基础资料改为只读展示 + 编辑弹窗

`components/projects/project-workspace.tsx`：

- 「项目（资料）」段落默认只读：`ProjectDetailsSummary` 用 label/value 列出项目名称、客户、电话、小区、楼栋、房号、负责人、系统平台、下一步截止、下一步负责人、下一步、截止说明；没有值的显示 `-`。
- 卡片右上角（`CardAction`）加「编辑」按钮，点击才打开 `Dialog`「编辑基础资料」，表单字段与保存逻辑不变（`updateProjectDetailsClient`，成功后写回项目状态并关闭弹窗）。
- 表单只在弹窗打开时挂载，重新打开会重新读取最新项目资料，取消不会留下未保存的选择。
- 项目指挥台卡片完全不变；`?tab=basic` 与项目入口地址不变。

## 第四轮（2026-10-21）：基础资料接管项目头部，跳转按钮并到一处

原来项目页有两张卡（项目指挥台 + 基础资料），信息重复。现在合成一张卡 `ProjectOverviewCard`：

- 卡片头部保留项目身份与状态：阶段 / 阶段状态 / 风险徽标、项目名、项目编号。
- 四颗操作按钮收在同一行：继续方案报价（主按钮）、编辑资料、返回项目列表、执行与资料（下拉）。「编辑资料」只在显示基础资料时出现，避免在别的段落编辑看不见的内容。
- 卡片主体就是只读的「基础资料」列表；原指挥台的六个摘要块并进来，补上 地址 / 等待对象 / 风险原因，**信息没有减少**（原「截止时间」等价于「下一步截止」）。
- 只在「项目（资料）」段落展开基础资料列表；切到方案报价、合同、工单等段落时这张卡只留头部，工作区不会被 15 行资料顶下去。
- 删掉不再使用的 `ProjectCommandCenter`、`ProjectDetailsCard`、`SummaryTile` 引用和 `formatDue`。

## 第五轮（2026-10-21）：只做减法的「方案报价」段落

用户要求把现在方案报价里面的内容做一次整合，随后明确「尽量简化而不是增多」。最终只做减法：

- 「方案报价」卡去掉重复的卡标题（顶部栏已经是「方案报价」），头部只留三个跳转按钮（`CardAction`）：打开点位设计 / 快速报价 / 打开报价单；正文只留「已保存点位草稿」。原来正文底部那排孤立按钮不再出现。
- `project-saved-design-summary.tsx`：四块统计并入一行文本（底图 / 点位 / 商品待选型 / 场景待确认），并删掉末尾那句与统计重复的灰色说明；楼层缩略图保留。
- 中间过程曾把报价单摘要（编号、状态、金额、未核验行数）加进这一页，用户要求以简化为先，已删除该组件，本页不再显示报价金额。
- 编辑与保存职责不变：报价仍在 `/quotes?projectId=` 保存，点位仍在 `/point-map?projectId=` 保存（ADR 0007），这里不新增第二条保存路径。

## 第六轮（2026-10-21）：继续收按钮

- 项目头部不再放独立的「返回项目列表」按钮（侧边栏「项目」已能回去）；它收进「执行与资料」菜单，用分隔线与段落项分开，渲染为 `href="/projects"` 的链接项。
- 项目头部剩两颗按钮：继续方案报价（主）+ 执行与资料（菜单）；在「项目（资料）」段落额外显示「编辑资料」。
- 顺带把项目头部的「返回项目列表」从 4 颗按钮降到 2–3 颗，手机上不再换行。

## 第七轮（2026-10-21）：去掉三处重复

由代理挑选的三处纯删除（用户回复「看你建议」）：

- 项目头部的风险徽标只在 `watch` / `blocked` 时显示；`正常` 是默认值，和「基础资料 · 风险原因」那一行重复，不再占位。
- 「基础资料」不再列「项目名称」——卡片大标题已经是项目名。
- 「方案报价」卡去掉「打开点位设计」：项目头部的「继续方案报价」本来就指向同一个 `/point-map?projectId=`，同一屏里不再放两个相同入口。

## 第八轮（2026-10-21）：继续并信息、砍占位内容

- **草稿摘要并成一行**：`已保存点位草稿 · r17 · 底图 1 / 1 · 点位 38 个（36 已定位、2 待定位） · 商品待选型 37 个 · 场景待确认 3 / 3 个`，去掉原来的标题行 + revision 徽标行（少一行、少一个徽标），楼层缩略图保留。
- **执行与资料里的四个占位段落只留入口**：合同 / 工单 / 客户交付 / 售后 原来各有 4 个通用说明块（如「标准工作内容」「工地实拍」），和具体项目数据无关；现在只保留段落标题 + 「查看合同 / 查看工单 / 查看客户交付 / 查看售后」按钮，`StagePanel` 变成标题 + 入口的紧凑卡。
- 段落取值、直达地址（`?tab=contract`、`?tab=work-orders`、`?tab=delivery`、`?tab=aftercare`）和各自的业务页面都没有变，符合 ADR 0007「保持原直达地址和业务实现」；成员 / 现场图片仍是有数据的项目内面板。
- 未做手机端段落切换器：那属于新增控件，与「只减不加」冲突，留待用户确认。

## 第九轮（2026-10-21）：执行类段落改成直达链接

用户确认后执行：合同 / 工单 / 客户交付 / 售后 不再作为项目内段落。

- 顶部栏「合同」从 `/projects/<id>?tab=contract` 改为 `/contracts?projectId=<id>`（仍带项目上下文）。
- 「执行与资料」菜单：工单 / 客户交付 / 售后 变成直达链接（→ `/work-orders?projectId=`、`/projects/<id>/presentation`、`/aftercare?projectId=`）；成员 / 现场图片 仍是项目内段落；返回项目列表留在最后。
- `WORKBENCH_WORKSPACE_TABS` 从 8 段降到 4 段（资料 / 方案报价 / 成员 / 现场图片）；`StagePanel` 与四个占位段落一并删除。
- **旧直达地址不静默失效**：`legacyWorkspaceTabHref` 把 `?tab=contract|workOrder|work-orders|delivery|aftercare` 转到对应业务页，`ProjectWorkspace` 挂载时 `router.replace` 过去。ADR 0007 要求「保持原直达地址和业务实现」，这里以跳转兑现，但入口形态已经与 ADR 0007 的描述（六项集中在「执行与资料」段落）不同，需要时另立 ADR 说明。
