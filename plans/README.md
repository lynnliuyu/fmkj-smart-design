## Direction Suggestions

- The current document is ready to become a PRD, but it is not yet implementation-ready. The highest leverage next step is to make the product rules testable before any UI or backend work begins.
- Treat "account type" and "paid plan" as separate concepts. The document already points in that direction at `docs/account-tier-and-upgrade-plan.md:341`, and making it explicit will prevent future migrations when enterprise pricing changes.
- Build permission checks as a shared server-side contract first, then let UI use it for display. The document names sensitive capabilities such as point maps, account management, billing, and child-account roles; those should not be independently reimplemented in screens.
