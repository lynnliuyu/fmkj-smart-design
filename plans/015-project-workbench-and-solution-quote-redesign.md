## 为什么要做

当前侧边栏点击“项目”后，页面同时承担了阶段浏览、项目筛选、项目详情预览、附件上传、跳转入口等职责。它更像一个项目流程演示页，而不是老板、运营负责人、项目经理每天真正使用的工作台。

重构后的项目区域要优先回答两个问题：

- 今天哪些项目需要处理？
- 打开某个项目后，下一步是什么、谁负责、什么时候前完成、从哪里继续做？

点位图和报价也不应该被拆成两个互不相干的入口。对全屋智能项目来说，空间点位、设备清单、数量、报价版本和客户确认是一条连续的“方案报价”工作流。

## 当前状态

- `components/projects/project-flow.tsx` 把 `/projects` 渲染成阶段轨道、按阶段过滤的项目列表、选中项目详情、附件上传和多个动作按钮。
- `components/projects/project-workspace.tsx` 把 `/projects/[id]` 渲染成若干 tab，但很多内容仍是占位说明；部分中文已乱码，必须先修复可见文案。
- `app/api/projects/route.ts` 暴露了 `risk`、`dueNote`、`nextAction`，但 `dueNote` 只是文本，不能可靠判断“今天到期”“近期到期”“等待客户/内部”。
- `scripts/neon-init.sql` 有 `projects.due_note`、`projects.next_action`、`projects.status_tone`、`projects.progress`，但缺少结构化的下一步截止时间、负责人、等待对象和风险原因。
- 侧边栏目前把项目相关能力拆得比较散。未来导航应保留“项目”作为管理入口，同时把点位图和报价合并成“方案报价”。

## 产品决策

- `/projects` 改成项目运营工作台，不再是阶段演示页。
- 项目优先级必须来自持久化字段，不能从展示文案里猜。
- 项目详情页改成“项目指挥台 + 模块工作区”。
- 点位图和报价合并为一个用户可理解的“方案报价”工作流。
- 桌面端项目列表使用紧凑表格或高密度行，不使用大卡片看板。
- 移动端可以退化成紧凑卡片。

## 数据模型要求

在 `projects` 上新增或迁移到以下结构化字段：

| 字段 | 用途 |
| --- | --- |
| `next_action` | 下一步动作的可读描述。 |
| `next_action_due_at` | 用于判断到期、近期到期和排序的日期时间。 |
| `next_action_owner_id` | 下一步负责人的用户 ID；账号映射不完整时可为空。 |
| `next_action_owner_name` | 下一步负责人的展示名兜底。 |
| `waiting_on` | 等待对象，取值：`none`、`customer`、`internal`、`vendor`。 |
| `risk_level` | 风险级别，取值：`normal`、`watch`、`blocked`。 |
| `risk_reason` | 当风险为 `watch` 或 `blocked` 时显示的原因。 |

兼容规则：

- 迁移期间可以继续保留 `status_tone`，但新 UI 优先读取 `risk_level`。
- `due_note` 可以继续作为展示兜底，但分组逻辑必须使用 `next_action_due_at`。
- 不允许通过硬编码中文标签来判断项目属于哪个优先级分组。

## 优先级分组规则

`/projects` 工作台按以下顺序分组：

1. **阻塞/风险项目**
   - `risk_level in ('blocked', 'watch')`
   - 先显示 blocked，再按最近的 `next_action_due_at`，再按最近更新排序。
2. **今天或近期到期**
   - `next_action_due_at <= now + 3 days`
   - 排除已经出现在风险组的项目。
   - 逾期项目排在最前，其次按截止时间从近到远。
3. **等待中**
   - `waiting_on in ('customer', 'internal', 'vendor')`
   - 排除已经出现在前两组的项目。
   - 必须清楚显示等待对象。
4. **普通进行中**
   - 未出现在以上分组的活跃、未归档项目。
   - 按 `updated_at desc` 排序。

售后或归档项目不应占据默认工作台，除非它们有开放售后任务或风险。

## 方案报价工作流

创建一个用户可见的统一工作流，命名为 `方案报价`。

它连接：

1. 点位规划
2. 设备/产品清单
3. 报价版本
4. 客户确认

导航含义：

- 侧边栏不应迫使用户在“点位图”和“报价”两个割裂入口之间选择。
- 全局 `方案报价` 可以作为设计/报价人员的跨项目队列。
- 在项目详情内，`方案报价` 是继续该项目点位和报价工作的主入口。
