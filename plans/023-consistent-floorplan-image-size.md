# Plan 023：统一底图尺寸与工作台图标比例

Status: DONE
Date: 2026-10-15

用户反馈新项目底图进入工作台后太小、图标挤在一起，并要求每次导出图片尺寸一致。

已证实两个比例问题：工作台先把底图适配窗口，却用固定 28 CSS px 图标，窗口越小图标相对图纸越大；共享导出此前保留输入分辨率（仅上限 6000），相同宽高比的 600 px 与 6000 px 图片产生不同大小的版面和图标占比。回归先复现两张输入导出布局不一致，然后修复。

`lib/point-map-image-size.mjs` 集中底图长边 3000、编辑逻辑长边 1500 和设备符号比例。净底工具、原图对照、XCLIP 渲染和应用共享导出沿用同一长边规则，短边等比计算，不拉伸。工作台用逻辑画布整体 fit/zoom，符号与图纸一起缩放；导出工程符号使用等价的 56 px。客户商品圆图与边距保留原语义，3000 指图形区域，不宣称包含说明卡的整个成品严格为 3000 px。

不裁剪或重写已有底图，不修改百分比安装坐标、CAD 绑定、affine 校准、报价或历史版本。渲染缓存提升版本，后续重画不会命中旧尺寸缓存。已有低分辨率图片放大不会增加原始细节。用户仍可放大 / 平移编辑密集点位。

验收：新增 3 项比例回归；全量 78 文件 / 830 项通过；类型检查与改动文件 Lint 通过。独立显示检查使用现有本地底图和 31 个已定位点位，在相同 616 px 图像宽度下符号宽度由 28 px 降为约 11.5 px，占比由 4.5% 固定为 1.87%。此项是独立浏览器比例检查，不代表已在数据库中保存新的客户设计。没有写主库或生成新的交付版本。

生产构建尝试失败：Next/font 拉取 Google Fonts Inter 时连接失败（`.local/image-size-build.log`）。没有修改字体实现或将网络失败伪报为构建成功。类型检查、全量测试和本次改动 Lint 均已实际通过。

## 用户复核后的修订

用户反馈工作台符号缩小后无法辨认，否决本计划中“编辑符号固定逻辑尺寸、跟随底图缩放”的做法。该部分由 ADR 0008 和 Plan 024 替代：固定可读屏幕符号、相邻点位分组、局部定位。长边 3000 / 等比准备、共享出图与不改安装坐标的决定保留。此前 11.5 px 的几何验证不再视为可读性验收。

2026-10-15 留白补充：用户随后确认裁去外围空纸并留约 3% 安全边距，本计划“不裁已有底图”由 Plan 025 和 ADR 0008 的整体迁移替代。禁止只换裁小图片仍保留旧百分比；实际 CAD 安装位置与历史固定版本继续保留。
