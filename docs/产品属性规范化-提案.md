# 产品属性规范化提案（开关 / 灯具为样板）

> 讨论稿。目标：把产品库从「每条自己写」变成「按类型填固定的几项 + 选项受控」，
> 这样报价、点位选型、采购、客户看方案都用得上同一份数据。

## 一、先约定属性的四种形态

| 形态 | 用在哪 | 好处 |
| --- | --- | --- |
| **枚举下拉** | 品牌、颜色、材质、协议、平台、供电方式、接线方式、安装方式、是否带驱动、光谱类型 | 不会写错、能筛选、能对比 |
| **数字 + 单位** | 键位数、路数、功率 W、开孔 mm、色温 K、电压 V、最大负载 W、额定电流 A、几芯线 | 选型规则能比较大小（≥ / ≤） |
| **受控文本** | 系列、厂家型号、系统货号 | 允许新增，但要按统一写法，避免同物多名 |
| **自由文本** | 描述 | 只给人看，不参与判断 |

原则：**凡是会影响「能不能装、多少钱、怎么配」的，都必须是枚举或数字**，不能是自由文本。

## 二、三个必须先定的模型决定

### 决定 1：颜色/键位这类差异，是一个货号还是多个货号？

| 做法 | 例子 | 好处 | 代价 |
| --- | --- | --- | --- |
| **独立货号**（建议） | `Aqara-D1-白-双键`、`Aqara-D1-灰-双键` 各一条 | 报价能区分价差、库存准确、采购单不会买错色 | 产品条数变多（789 条可能翻倍） |
| 单货号 + 属性 | 一条 `Aqara D1 双键`，颜色写属性 | 表更短 | 白色灰色价差无法体现，库存混在一起 |

> 建议：**有价差或库存差异的（颜色、键位、是否智能）拆成独立货号**；纯描述性的（材质）留在属性里。

### 决定 2：品牌 / 系列 / 型号 要不要做成受控下拉？

现状（你库里 789 条实测）：

| 字段 | 现状 |
| --- | --- |
| 品牌 | 27 种写法，自成体系（易来/yeelight、领普/Linptech…），6 条空 |
| 厂家型号 | 只有 70 种写法，**719 条（91%）是空的** |
| 系列 | **没有这个字段** |

- 做成受控：能杜绝「小米 / 小米科技 / MI」这类漂移，筛选和配套判断才准；代价是要维护一份品牌/型号库。
- 做法建议：我从现有 789 条生成**品牌库初稿**（27 个）和**型号库初稿**（70 个），你审核增补；新品牌走「申请新增」。

### 决定 3：生态平台要不要支持多值？

现状：**单值**，而且 366 条（46%）是「其他」。一个设备常同时支持米家 + Apple Home，现在只能填一个。

建议：改成**多值**（像通信协议那样），并把「其他」改成「未标注」，避免「其他」变成垃圾桶。

## 七、落地方式（谁做什么）

1. **你们定规则**：上面三个模型决定 + 每类要哪些属性（哪些必填、哪些可有可无）。
2. **我改代码**：把新属性加进设备类型定义、把自由文本改成枚举、改必填、跑测试（每类约 30 分钟）。
3. **我建字典初稿**：品牌库（27 个）、型号库（70 个）、颜色/材质/安装方式等枚举，从现有数据生成，你审核。
4. **我出填写模板**：按新规则生成精简表（每类只留要填的列），工人照着填。
5. **工人填**：按模板逐条补齐；我出「体检清单」把每条缺什么列出来。
6. **导入 + 校验**：导入后我跑一遍校验，把问题列出来再补。

## 八、已定的决定（2026-10-23）

| 决定 | 结论 | 落地情况 |
| --- | --- | --- |
| 变体是否拆独立货号 | **拆**（颜色/键位/是否智能/功率开孔各自独立） | 规范已写入《产品变体与命名规范》；系统本身支持「系列(父)+子货号」 |
| 品牌/系列/型号受控 | **做**（从现有数据生成初稿，新增走申请） | ✅ 已做（字典表 + 种子 + 后台「品牌/型号字典」弹窗 + 导入严格校验 + 产品表单联动下拉） |
| 生态平台多值 | **改多值**，「其他」改「未标注」 | ✅ 已做（迁移已回填 789 条；导入导出用分号；后台改多选） |
| 灯具功率/开孔/调光/驱动必填 | **功率与调光必填；嵌入式（筒灯/射灯/平板灯/格栅灯）开孔也必填** | ✅ 已改 |
| 传感器探测方式/距离必填 | **两者都必填**，探测技术改枚举（红外/毫米波/超声波/光电/其他） | ✅ 已改 |
| 点位选型必需是否扩展 | **暂不动**：会改变做点位图时的填写项，等实际做一次方案再定 | 未做 |
