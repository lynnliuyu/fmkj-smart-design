# 账号体系开发路线图

## 1. 目标

本路线图用于把账号等级、企业团队、权限控制和付费升级体系拆成可执行研发任务。它依赖以下文档：

- `docs/account-tier-and-upgrade-plan.md`
- `docs/account-system-technical-spec.md`

## 2. 里程碑总览

| 里程碑 | 主题 | 主要产出 | 优先级 |
| --- | --- | --- | --- |
| M1 | 基础账号和套餐能力 | 账号类型、套餐、订阅、免费版限制 | P0 |
| M2 | 统一权限系统 | PermissionService、拒绝原因、服务端校验 | P0 |
| M3 | 个人升级版 | 付费入口、个人升级、点位图解锁 | P1 |
| M4 | 企业组织和子账号 | 企业、成员、角色、权限、成员限制 | P1 |
| M5 | 企业付费和到期处理 | 企业订阅、宽限期、过期锁定、订单 | P1 |
| M6 | 管理后台和运营能力 | 超管后台、套餐管理、订单、操作日志 | P2 |

## 3. M1：基础账号和套餐能力

### 3.1 后端任务

- 创建账号类型枚举。
- 创建订阅状态枚举。
- 创建套餐类型枚举。
- 创建 users、account_profiles、plans、subscriptions、projects 表。
- 初始化免费版、个人升级版、企业版套餐配置。
- 实现当前用户上下文接口 `/api/me`。
- 实现项目创建接口中的免费版项目数量限制。

### 3.2 前端任务

- 账号中心显示当前账号类型。
- 账号中心显示当前套餐。
- 项目列表显示当前项目额度。
- 免费用户创建第 2 个项目时展示升级弹窗。

### 3.3 测试验收

- 免费用户可以创建第 1 个项目。
- 免费用户创建第 2 个项目失败。
- 免费用户接口返回 `PROJECT_LIMIT_REACHED`。
- `/api/me` 返回账号类型、套餐和套餐限制。

## 4. M2：统一权限系统

### 4.1 后端任务

- 创建 permissions 表。
- 初始化权限点。
- 创建 PermissionService。
- 实现 `can(user_id, permission_code, resource)`。
- 实现 `assertCan(user_id, permission_code, resource)`。
- 统一返回拒绝原因。
- 将项目创建和点位图接口接入 PermissionService。

### 4.2 前端任务

- 前端根据 `/api/me` 的权限摘要隐藏不可用入口。
- 不可用功能展示对应升级提示或无权限提示。
- 点位图入口支持锁定态。

### 4.3 测试验收

- 未登录用户返回 `NOT_AUTHENTICATED`。
- 被禁用账号返回 `ACCOUNT_DISABLED`。
- 免费用户访问点位图返回 `POINT_MAP_NOT_INCLUDED`。
- 普通用户访问平台管理接口返回 `PLATFORM_ADMIN_REQUIRED`。

## 5. M3：个人升级版

### 5.1 后端任务

- 实现套餐列表接口 `/api/plans`。
- 实现订阅升级接口 `/api/subscription/upgrade`。
- 实现订单创建和支付结果回写。
- 个人升级成功后更新订阅为 ACTIVE。
- 个人升级成功后解除项目数量和点位图限制。
- 个人取消续订后保留到期前权益。
- 个人到期后降级为免费版限制。

### 5.2 前端任务

- 升级弹窗展示个人升级版权益。
- 支持月付和年付选择。
- 支付成功页展示权益变化。
- 账号中心展示到期时间、续费和取消续订入口。

### 5.3 测试验收

- 免费用户升级成功后可以创建多个项目。
- 免费用户升级成功后可以使用点位图。
- 支付失败不改变订阅权益。
- 取消续订后到期前仍保持个人升级版权益。
- 到期后超额项目只读或归档。

## 6. M4：企业组织和子账号

### 6.1 后端任务

- 创建 organizations、organization_members、roles、role_permissions 表。
- 初始化企业默认角色：管理员、编辑者、查看者、财务。
- 实现创建企业组织接口。
- 实现邀请成员接口。
- 实现修改成员角色接口。
- 实现禁用和移除成员接口。
- 实现子账号数据转移流程。
- 企业项目归属支持 owner_type = organization。

### 6.2 前端任务

- 企业管理后台：企业资料。
- 企业管理后台：团队成员列表。
- 企业管理后台：邀请成员。
- 企业管理后台：角色选择。
- 企业管理后台：移除成员时选择数据接收人。

### 6.3 测试验收

- 企业主账号可以创建企业组织。
- 企业主账号可以邀请成员。
- 企业主账号可以修改成员角色。
- 企业子账号只能访问授权项目。
- 企业子账号无权限时返回 `ROLE_PERMISSION_DENIED`。
- 移除成员必须选择数据接收人。
- 被移除成员不能访问原企业项目。

## 7. M5：企业付费和到期处理

### 7.1 后端任务

- 企业订阅绑定 subject_type = organization。
- 企业升级成功后创建组织和企业订阅。
- 支持企业成员数量限制。
- 支持企业订阅取消续订。
- 支持企业订阅进入 GRACE_PERIOD。
- 支持企业订阅进入 EXPIRED。
- 过期状态锁定新增、编辑、邀请成员和点位图编辑。

### 7.2 前端任务

- 企业套餐选择页。
- 企业付款流程。
- 企业订阅状态页。
- 企业过期和宽限期提示。
- 企业成员超额提示。

### 7.3 测试验收

- 企业版可以创建团队和子账号。
- 企业成员数达到上限后不能新增成员。
- 企业订阅宽限期内可以查看数据。
- 企业订阅宽限期内不能新增项目或邀请成员。
- 企业订阅过期后付费功能被锁定。

## 10. 风险和处理

### 10.1 权限散落风险

风险：

- 每个接口独立写权限判断，后续难以维护。

处理：

- 所有业务接口必须调用 PermissionService。
- Code review 时检查是否绕过统一权限。

### 10.2 套餐和账号类型混用风险

风险：

- 用 account_type 直接判断付费权益，后续套餐变化会困难。

处理：

- account_type 只判断身份类型。
- 付费能力必须读取 subscription 和 plan.limits。

### 10.3 降级数据丢失风险

风险：

- 用户降级后项目或点位图被误删。

处理：

- 降级只锁定或只读，不自动删除数据。
- 删除必须由用户主动操作或管理员按流程操作。

### 10.4 企业成员数据归属风险

风险：

- 子账号被移除后，其创建的数据无人维护。

处理：

- 移除前必须选择数据接收人。
- projects.transferred_from_user_id 记录来源。
