# 点位图、商品圆图与方案 PDF 导出工作流

本文描述已经接通的保存与出图流程。工程编辑图、无点位风格净底和带商品点位的导出成品分别保存，避免复用成品时残留旧图标。

客户报价可以包含默认型号与待核资料；报价行、报价 PDF、方案 PDF 均明确标注未核验。该标识随报价快照与完整交付版本保存，不因后来产品库核验而改写旧版。未核验默认报价允许保留未定位点，图中不伪造其安装位置，仍在待定位清单说明。项目换型和报价删除联动按 [ADR 0006](adr/0006-project-quotation-defaults-and-linked-deletion.md) 执行。

## 数据与输出

| 入口 | 点位和位置来源 | 底图与符号 | 商品映射来源 |
| --- | --- | --- | --- |
| 点位工作台画布 | 当前编辑草稿 | 工程 `floorplanDataUrl`，同源设备 SVG | 编辑器中的点位选型；画布仍以类别符号展示 |
| 高级工具 → 草稿检查 PNG | 当前工作台草稿，包含尚未保存的位置修改 | 有效 `presentation` 风格净底与商品圆图；未绑定则用工程净底 | 当前项目最新已保存报价，再回退到点位 `productId` |
| 报价 PDF | 先保存当前报价，再生成完整交付版本 | 同一校准与圆图渲染，每层图独占一页 | 固定交付版本内的报价和图片；无点位方案的项目仍可导出纯报价 |
| 客户交付页 PNG / PDF / CSV / JSON | 当前资料先生成固定版本，或直接使用选定的历史版本 | 同一校准与圆图渲染，每层图独占一页 | 同一份版本内的报价、商品展示素材和场景 |

工作台 PNG 可以用于当前草稿检查。正式交付从三段入口的“客户交付”进入：先保存本页点位及报价，再在交付页生成最新版。报价 PDF 先保存本页报价；交付页读取服务器已经保存的资料，不读取另一标签页尚未保存的编辑。交付页的 PNG、PDF、CSV 和完整 JSON 都共用固定版本，预览状态下载或打印会先生成固定版本；明确选择的历史版保持该版。详见 [ADR 0007](adr/0007-fixed-delivery-outputs-and-editor-responsibilities.md)。

## PDF 公司署名

项目方案册页头使用紧凑排版，报价明细可跨页，表头在续页重复；房间列与数量、金额列分别保留固定宽度。报价单和项目方案册共用 `lib/document-brand.ts` 的公司名“繁梦空间智能设计”与原始 Logo。首页显示 Logo 和公司名，每页的下方页边区域显示公司名；打印文件标题也包含公司名。页边署名使用浏览器的 `@page @bottom-center`，避免绝对定位的打印正文导致普通固定页脚只落在最后一页。导出前同样等待 Logo 解码。浏览器导出后逐页核对署名，楼层图继续每张独占一页。用户上传的历史 PDF 附件保持原文件。

## 首次准备底图

1. 从原始 DWG / CADCraft 提取工程净底，核对楼层、裁切窗口、图片尺寸和 CAD 绑定。工程底图写入楼层 `floorplanDataUrl`；点位继续使用这张工程图的完整图片百分比坐标。
2. 准备无点位、无商品圆圈和编号的风格净底。已经叠好旧点位的彩平 PNG 是交付成品，不能再次当作底图使用。原风格图单独保存，不让导出流程重画建筑或家具。
3. 在工程图和风格图实际像素上选择对应墙角、电梯角、门洞等锚点，覆盖整幅建筑主体，求工程百分比到风格百分比的 affine。记录全部锚点及残差，不为隐藏局部生成偏移而删除难点。
4. 准备校准 JSON。`floors[]` 至少包括 `floorName` 或 `floorId`、`engineeringFile`、`presentationFile`、`width`、`height`、`matrix`、`anchors[{source:{x,y},target:{x,y}}]`。图片文件路径供本机打包脚本读取，百分比坐标以完整图片左上角为原点。

矩阵顺序是 `[a,b,c,d,e,f]`：

```text
styleX = a * engineeringX + c * engineeringY + e
styleY = b * engineeringX + d * engineeringY + f
```

两个轴的输入和输出都是百分比。渲染时才投影点位；工程点位 `x/y`、两张原图的尺寸和几何均不改写。

## 打包、导入与数据库保存

先保存点位草稿，导出或读取该项目最新完整 plan JSON。打包脚本接受完整 plan、`{plan: ...}` 或 API 的 `{data: ...}` 外层形式：

```sh
node scripts/create-point-map-presentation-bundle.mjs \
  --plan /absolute/path/saved-point-map.json \
  --calibration /absolute/path/presentation-calibration.json \
  --output /absolute/path/presentation-backgrounds.json
```

脚本核对校准文件中的工程图片字节与保存 plan 的工程图片一致，核对原风格 PNG 尺寸，然后生成 `format: "fmkj-point-map-presentations"`、`version: 1` 的独立 JSON 包。包中携带项目 ID、楼层 ID、原风格图片 data URL、尺寸、来源指纹、矩阵和锚点，不携带可执行命令。

在点位工作台展开“高级工具”，再展开“客户展示底图”，点击“导入已校准风格底图”。导入对项目、楼层、工程来源、矩阵和锚点执行整包校验，通过后写入当前草稿；随后点击“保存到数据库”。导入成功提示不是数据库保存成功，需确认页面出现数据库已保存状态，再到“客户交付”导出。

展示资料保存在 `floor.presentation`，工程 `floorplanDataUrl` 与 CAD 绑定继续保留。仅增加或更换展示底图时，`samePointMapQuoteSource` 判断报价来源未变，不重算报价预览或覆盖数据库报价。由此出现“点位 r40、报价 r39”可能只是附件版本变化，不能仅凭 revision 不同推断商品已变。

## 底图校准如何失效

`sourceFingerprint` 是工程 `floorplanDataUrl` 完整字符串 UTF-8 字节的 SHA-256，区别于校准审计文件中记录的 PNG 文件字节 SHA-256。工程图更换或编码字符串变化后，原指纹不再匹配，需要重新核对与绑定。

导入要求锚点非共线、横纵覆盖各至少 50%，矩阵不能镜像或退化，投影范围应落在允许边界内，最大二维百分比残差不得超过 2%。导出再次核对工程来源指纹、校准与风格图片实际尺寸。

三个入口都请求 `background: "presentation"`：

- 有有效风格净底：用它叠加实时点位。
- 未绑定风格净底：使用工程净底。
- 已绑定但来源、尺寸或校准失效：明确报错并停止导出，不暗中更换底图。

底层渲染函数支持显式 `engineering` 模式；现有三个展示导出入口默认使用 `presentation` 规则。风格图通过残差检查也只用于客户展示，施工仍核对工程原图。

## 商品图片如何对应

三个导出入口共用 `buildPointMapProductVisuals`，只处理当前渲染楼层的已定位点位：

1. 从当前项目已保存报价的 `pointIds` 精确查找该点位的主商品。报价映射优先于 `point.productId`；没有报价覆盖时才使用点位关联。不能仅根据图标、类别或商品名称推断商品。
2. 通过点位 `materials[].productId` 排除明确配套的轨道、配件和服务，避免其覆盖主设备；一个点位在报价中匹配多个不同主商品时报错。
3. 图片优先读取报价行的 `image`。报价 API 有产品快照时通常返回快照图片，无快照时读取产品库；报价行缺少可用图时，再读取当前产品库的同商品图片。占位图不作为真实商品图。
4. 已关联商品但没有可用图片，或图片加载失败时，PNG 和两个 PDF 都停止并说明原因。未关联任何商品的点位继续画分类圆形图标。
5. 商品照片先保守识别透明、纯白或 JPEG 近白外围留白；同源图片会将边缘连通的白色画布转为透明，再按取景范围的原始比例 contain 于圆内。白色机身若由轮廓或阴影包围会保留，设备触边或无法读取像素时回退原图；保留约 4% 边距，不确定底色时使用全图。这里只改变显示取景，不改产品原图。周边保留分类色底、描边和轻阴影，不拉伸成正方形。每层只加载该层实际使用的商品图片，同一照片的取景结果在本层点位间复用。客户交付图的圆图文字使用统一类别名（单开、双开、三开、四开、监控、AP、AC、四寸屏、中控大屏、中枢网关等），工作台和报价数据继续保留稳定点位编号。

商品圆图默认直径为底图宽度的 6%（72–144 个逻辑像素），约为原默认尺寸的 2.4 倍。圆图和编号联合避让，必要时只移动展示圆图，并用细引线及锚点指回实际安装位置；工程百分比坐标与已保存点位不变。排不下时明确报错，不隐藏点位。商品输出按需提高画布像素密度，本项目三层均为 3200 像素宽；这能改善商品照片与文字的放大显示，不能恢复原底图中不存在的建筑细节。PNG、报价 PDF 和项目方案页共用这一渲染规则。

圆形边框使用 0.8 个逻辑像素的低透明度分类色，浅色底、细引线和轻阴影共同保持辨识度。商品主体按取景框最长边等比放大并通过圆形蒙版显示；原始照片不覆盖，外围白底透明化仅作用于本次渲染画布。浏览器原生 `ImageData` 的尺寸和实例在读写像素时保留，避免处理后出现空圆。项目方案页每层提供“下载 PNG”，直接下载同一张用于 PDF 的完整分辨率图片。

报价关系仅用于导出视觉，不写回点位 `productId`、`usage` 或选型核验快照。图上出现商品照片不等于该 SKU 已完成采购核验。

## 调整后的操作顺序

**移动点位、修改类别或更换商品：** 在工程画布完成编辑并保存点位草稿。若点位保存触发了报价预览更新，进入报价页核对并保存，使数据库报价成为三个入口共同读取的版本。报价映射优先，因此仅改点位关联却保留旧报价时，导出仍可能显示旧报价商品。

**修改报价商品、数量、价格或优惠：** 在报价页完成调整并保存。报价 PDF 点击导出时先保存本页编辑，再生成固定交付版本，以该版本的明细、实际折后单价、小计、金额和图片绘制页面。保存或来源核对失败停止打印。它不会替用户保存另一页面尚未保存的点位位置。

**整理产品照片：** 在产品管理的商品行菜单进入“展示图片”，独立保存原始来源、展示图、裁切、主体大小、核验状态和依据。`product_visual_assets` 按商品 ID 保存，不改目录原图、SKU、参数或价格；更新素材后“生成最新版”即冻结当前展示图。普通报价编辑需要刷新照片时点击“更新商品图片”：专用接口仅更新当前草稿未删除行的图片与展示素材字段，保留尚未保存的价格、房间、数量和删除编辑；以报价 ID 和更新时间防止覆盖其他人的修改。已保存旧报价和旧交付版本均不回写。详见 [产品采集与入库指引](product-catalog-agent-guide.md)。

**微调展示圆图：** 方案交付页点击“微调排版”，选择并拖动商品圆图或文字；方向键每次微调 0.2%，Shift 为 1%。点击“保存排版”后生成新版。`point.display.markerOffset/labelOffset` 独立保存，安装 `x/y`、设备数量与报价不变。“复位所选排版”恢复自动避让。越界或放不下会报错，不静默挪回或隐藏设备。

**只换展示风格或重校准：** 重新制作无点位底图或校准包，导入并保存点位草稿即可；商品报价保持原样。移动设备或换商品通常不需要重新生成风格底图。

**场景与商品联动：** 方案交付页点击场景可高亮关联点位；点击圆图或文字可查看该点位的报价商品、单价、关联场景和控制对象。场景来自已保存 `plan.scenes`，没有场景时显示待补充，不自动填入已经确认的场景。高亮是页面辅助，不烧录到 PNG/PDF。

**出图：** PNG 只渲染需要的楼层；两个 PDF 复用相同楼层结果，每张点位图独占一页。图片全部生成后等待打印 DOM 图片解码与字体就绪，再打开浏览器“存储为 PDF”。生成失败显示原因，不沿用不匹配的静态成品。方案交付页可同时下载报价 CSV 与完整版本 JSON。

渲染以楼层内容 SHA-256 为键：底图、校准、点位、展示偏移、所用商品图片与裁切变化才使对应楼层失效；价格和场景文字不触发重画。浏览器 IndexedDB 缓存最多 24 层 / 128 MiB，内存最多 4 层 / 32 MiB；禁用存储或容量不足时仍正常导出。商品解码与裁切也复用。改变一张多个楼层共用的商品照片会更新这些楼层；并非修改既有 PNG 的少量像素，受影响楼层重新合成。

## 完整交付版本

`project_deliveries` 保存不可变的 V1、V2 等：完整 plan（工程图、展示净底和校准）、场景、报价实际金额、商品展示图片字节和裁切资料。生成在同一数据库事务中读取，校验点位、房间、数量及配套材料；报价对点位商品的明确覆盖仍保留。仅版本号差异不认为报价失效。完全相同的内容复用已有版本，不产生空的新版本。

页内版本选择器读取旧版时不查询今天的商品图片或报价，后续替图、调价和挪点不会改写旧版。变化说明展示增删改点位、图片、商品、场景、报价及来源覆盖。实际展示图必须先归档为 `public/assets` 本地资源或可验证的栅格 data URL，避免历史依赖远程图片失效；原始来源可保留远程 URL 作依据。不会自动抓取任意 URL。

高级工具包含 JSON、草稿 PNG、云端恢复、设计确认、彩平与 CAD。新项目或云端冲突时工具自动展开，避免隐藏首次导入或恢复路径。

旧“点位确认版本”已下线（2026-10-21，功能从未被使用）：工作台只编辑草稿，需要整套复现时选择方案交付 V 版本。历史只读访问保留项目可见性校验，新版本生成需要编辑权限和点位权益。

## 后续提案册扩展边界

参考《家华 全屋智能点位及场景设计》的内容组织，可以继续增加分房间商品卡片、总体架构和场景表达。但当前交付链路已经明确为“独立净底 → 校准投影 → 已保存报价商品圆图 → 场景与报价分页”，不能把未实现的卡片、生成场景或历史报价恢复写成现有功能。参考文档只提供版式和表达方式，不将其客户资料、型号或场景混入本项目。

架构决策见 [ADR 0004](adr/0004-calibrated-presentation-backgrounds.md)。

底图尺寸规则：净底和共享渲染器统一图形区域长边 3000 px，短边按比例计算；客户圆图保留现有排版和必要留白，输出文件可包含边距。工作台使用清晰的固定屏幕尺寸及相邻点位分组，按 ADR 0008 定位和放大；编辑图标不再随底图缩成不可读的小图。分组与相机状态不进入 PNG / PDF。更新渲染规则时提升缓存版本，不复用旧尺寸缓存；不修改工程图指纹、校准矩阵、安装坐标和已保存交付版本。

工程净底留白按 Plan 025 / ADR 0008：新图先裁外围空纸并留约 3% 边距，再统一长边。已有图通过“整理底图留白”同步变更指纹、百分比坐标、CAD 窗口和 affine 矩阵，保留原锚点对应关系与实际安装位置。独立风格图片保持原样；它的校准视觉和历史固定交付不变。不能将普通助手草稿合并导入当作坐标迁移。

工作台的灯光 / 开关“图纸对照”仅用于设计核对，与客户展示底图独立。切图不改变 PNG / PDF 来源，也不另算采购或报价；完整 JSON 保留已保存的参考图资料，历史固定交付仍使用原快照。详见 ADR 0009。
