# 产品变体与命名规范（2026-10-23 定）

> 本文记录三个已定的决定：**变体拆独立货号**、**品牌/系列/型号做受控**、**生态平台改多值**。
> 整理产品时按本文执行；系统里已有的机制直接用，不另造一套。

## 一、系统里已有的三种"目录类型"（catalogKind）

| 值 | 含义 | 能不能用于点位选型 |
| --- | --- | --- |
| `legacy` | 旧产品，还没整理成具体 SKU | ❌ **直接排除**（提示"旧产品尚未整理为具体 SKU"） |
| `series` | 系列（父记录），下面挂具体货号 | 本身不参与选型，只用来归组 |
| `sku` | 具体货号（子记录，可带 parent） | ✅ 可用 |

**你库里现状（789 条）**：`sku` 95 条、`series` 8 条、**`legacy` 686 条（87%）**。
这 686 条在选型里全部用不上——整理的第一步就是把它们升级成 `sku` 或 `series`。

## 二、决定 1：变体拆独立货号

**规则**：以下差异**必须拆成独立货号**（各自有价格、库存、采购记录）：

| 差异 | 为什么拆 |
| --- | --- |
| 颜色 | 白/灰/黑常不同价，库存不能混 |
| 键位数（单/双/三/四键） | 价格不同，点位选型要按键数匹配 |
| 智能 / 非智能 | 完全不同产品 |
| 功率 / 开孔尺寸（灯具） | 价格与安装都不同 |
| 是否带网关/驱动 | 配套与报价不同 |

**不拆**（留在属性里）：材质（除非价差明显）、描述差异、包装。

### 推荐结构：系列(父) + 变体(子)

```
系列记录：catalogKind=series，名称「Aqara D1 智能墙壁开关」，不带价格/库存
   ├─ 子 SKU：Aqara D1 双键 白色    catalogKind=sku，parent=系列，颜色=白，键数=2
   ├─ 子 SKU：Aqara D1 双键 灰色    catalogKind=sku，parent=系列，颜色=灰，键数=2
   └─ 子 SKU：Aqara D1 三键 白色    catalogKind=sku，parent=系列，颜色=白，键数=3
```

好处：点位选型会**按键位数自动挑对应的子货号**（系统已有这个逻辑：`leafForKeyCount`）；
报价时颜色价差也能体现。

## 三、命名规范

### 1. 系统货号（唯一标识，全系统认它）

```
<品牌代码>-<厂家型号>-<变体码>
例：AQ-QBKG28LM-W2   （Aqara / 型号 QBKG28LM / 白色双键）
    YL-Yeelight-M2-B3
```

- 全大写、只用字母数字和连字符，**不要中文和空格**
- 品牌代码统一（Aqara=AQ、易来=YL、小米=MI、领普=LP、苏米=SM…），由品牌字典固定
- 变体码约定：颜色 W 白 / G 灰 / B 黑 / GD 金；键数 1/2/3/4

### 2. 产品名称（客户看到的）

```
<品牌> <系列> <类型> <变体>
例：Aqara D1 智能墙壁开关 双键 白色
```
- 不写价格、不写"特价""爆款"这类营销词
- 同一系列的各变体，名称前缀保持一致

### 3. 厂家型号 / 系列

| 字段 | 填什么 | 例 |
| --- | --- | --- |
| 系列 | 厂家/品牌的产品系列名，同系列各变体一致 | D1、H1、妙控、云光 |
| 厂家型号 | 厂家自己的型号（可变体不同） | QBKG28LM、QBKG29LM |
| 品牌 | 从品牌字典里选（受控） | Aqara / 易来 / 小米 |

> 现状：厂家型号 **91% 是空的**。整理时优先补这个，它是客户对型号、跟厂家对货的依据。

## 四、决定 2：品牌 / 系列 / 型号 做受控

- 品牌、系列、型号改为**从字典选择**，不再自由填写；新增走"申请新增"。
- 初稿从现有数据生成：品牌 27 个、型号 70 个（我去重后给你审核）。
- 好处：杜绝「小米 / 小米科技 / MI」「Aqara / 绿米」这类同物多名；筛选和配套判断才准。

## 五、决定 3：生态平台改多值

- 现状：单值，且 **46%（366 条）填的是「其他」**。
- 改成多值（像通信协议那样），例如一个设备可同时是 `米家 + Apple Home`。
- 「其他」改为「未标注」，避免它变成垃圾桶。

## 六、整理顺序（建议）

1. **把 686 条 `legacy` 升级**：能确定是具体货号的改 `sku`；有系列关系的建父系列 + 子货号
2. **补设备类型**（91 条空）——没它参数和选型都用不上
3. **补必填参数**（供电方式缺 517 条最多）
4. **补厂家型号 / 系列**（型号 91% 空）
5. **统一品牌写法、生态平台改多值**
6. 参数核验、价格核验：走后台流程，别在表格里自己填"已核验"
