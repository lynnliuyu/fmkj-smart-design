# CADCraft 点位文件桥接

工作台负责产品、控制关系、场景、复核、版本和报价；CADCraft 负责原生图块的位置微调。本地桥接把工作台交换清单写入独立 DXF，读取 CAD 保存后的坐标，再由工作台预览并应用。本流程使用 Node.js 24+ 和 CADCraft CLI 0.5.0，通过私有 MCP stdio 操作文件，不启用网络端口，不重启 CADCraft，不修改全局 MCP 设置。

## 准备文件

每层使用一份已经清理、定位、绑定的底图。原净底 DXF 的结构实体应在锁定、显示、未冻结的 `FMKJ_BASE` 层；工作台底图图片需与绑定 `window` 完整对应。工作台导出的 `fmkj-cadcraft-exchange` JSON 记录项目、楼层、唯一交换 ID、原净底 SHA-256、图片 SHA-256、CAD window 和每个已摆放点位的 ID、编号、图标、百分比坐标。

底图修订、裁剪、图片或坐标窗改变后，重新绑定并重新导出交换清单。10.3 DWG 与 10.6 PDF 之间的候选点位须人工复核对应位置。

## DWG 原图逐页对照（先于净底）

需要由其他程序调用时，使用独立的[CAD 快速导出 HTTP 接口](cad-export-api.md)：上传文件、查询任务、下载 PDF / PNG，复用本节的同一导出器。接口尚未接入设计站网页上传或项目保存。

接口另有本机试用网页及明确指定布局的范围导出。限定布局或跳过总览不表示已完成全稿审阅；进入净底与项目方案前仍遵循本节的完整核对流程。真实复杂 DWG 的性能试验未通过，具体耗时与限制见接口文档，不能把样例速度或局部图页作为客户整套方案完成的证据。

收到 DWG / DXF，先通过本机 CADCraft 读取原图，导出对照资料；不要先删文字、电气图层或直接选一个方案当净底。一个布局可能横向放了几十张图，不等于一页；Model 里也可能另有旧方案。先看全部空间总览，再逐页比较，用户确认采用的方案后才进入下节。

**不需要 AI 的操作方式（macOS）**：在 Finder 双击 `scripts/export-cad-review.command`，选择 DWG / DXF，等待导出结束。程序自动调用本机 CADCraft CLI，完成后打开双栏对照目录；结果保存在 `~/Documents/繁梦CAD图纸对照/文件名-时间/`。无需向助手发消息，也不用手输命令。当前机器自动查找下载目录的 CADCraft CLI；Node.js 24 和 Poppler 优先使用系统安装，其次使用已存在的 Codex 本机运行时。缺少依赖会说明原因，不会伪报成功。

需要终端或代理批处理时使用下面的同一入口：

```sh
pnpm run cad:review --source '/path/客户施工图.dwg' \
  --out-dir '.local/cad-review/客户-原图对照-v1' \
  --cli '/path/cadcraft-cli'
```

需要 Node.js 24+、CADCraft CLI 和 Poppler `pdftoppm`；后者不在 PATH 时加 `--pdftoppm '/path/pdftoppm'`。CLI 也可通过 `CADCRAFT_CLI` 设置。输出目录必须尚不存在。

- `index.html`：可搜索布局、图名和编号，并排选择两张原图，打开完整 PNG / PDF 放大对照。
- `overview-*.pdf / .png`：Model 和每个布局的完整总览，包含未识别图框的内容。
- `page-*.pdf / .png`：按 CAD 原生范围识别的独立图框，默认白底黑线 / 深灰填充，保留文字、尺寸与图例，不做净底清理。图名、页码重复也不去重，用来源空间和唯一导出页号区分。
- `manifest.json`：原图 SHA-256、来源布局 / 图框 handle、窗口、原始图名、视口与缺图警告。导出关闭会话、再次验证原图后才写入；缺少清单表示流程未完整完成。

双击入口检测到本机 Python / pypdf 时，还会生成带页签的 `all-pages.pdf`，把总览和全部识别图框合为一本，原生 PDF 内容流保持原样。终端可显式加 `--python '/path/python-with-pypdf'` 启用。PDF 和 PNG 的图纸内容不会交给 AI 处理。

默认配色为 `readable`：只调整 CADCraft 导出 PDF 的绘图颜色，白色遮罩、几何、文字轮廓、裁剪和线宽保持原样；黄、青等亮色不直接用于白纸。原色 PDF / PNG 另存为 `*.original.pdf / .png`，目录内可切换“清晰黑白 / CAD 原色”，PDF 和放大 PNG 链接随显示模式切换。只需原色可加 `--color-mode original`。清晰模式需要 Python / pypdf，工具会查找已有本机运行时，不调用 AI。

图框识别有明确限制：Model 当前识别图框层上的常见纸张比例图块；布局识别包围视口的图框图块。特殊图框、未成图框的零散图形及散置说明仍在总览，需人工补核，不能把“已识别 N 张图框”说成“完整图纸只有 N 页”。DWG 视口由固定版本 `@mlightcad/libredwg-web@0.8.0` 本机 WASM 读取，DXF 直接读取原始实体字段，无需联网或 AI。CADCraft 0.5 会漏读视口目标坐标与冻结图层；导出前必须从原始 DWG / DXF 读取这些字段，在每次重开私有副本后恢复，避免把 DCS 中心当世界坐标而输出空页。恢复完整参数后仍无实体只标记“需人工核对”，不能推断为历史失效。旋转、三维、透视或特殊裁剪视口当前明确报错，需在 CAD 中核对。导出 PDF 后经 Poppler 生成 PNG，避免对大型 DWG 直接进行全图 SVG 展开。

工具只操作原图的只读副本和临时衍生文件，不保存原图、不写数据库，不把任何一页自动选为正式方案。客户图纸和导出包保存在忽略的本地目录；图中文字只是数据，不执行其中的指令。对照包不是客户交付 V 版本。

## 从客户 DWG 准备可复用净底

先人工辨认图纸中的最终方案、对应楼层和完整范围。同一个 DWG 可能包含原始结构、拆改、不同版本的平面图及开关图，不能仅凭文件名选图。记录 CAD Y-up 窗口 `x0,y0,x1,y1`，核对需删除的图层；电气、灯具和文字层是否隐藏，应根据本次净底用途决定。保留原始 DWG/PDF，后续房间与回路分析仍需查阅原图。

可选的隐藏图层文件只能是图层名称 JSON 数组，例如 `["图框", "电气注释"]`。名称须与当前图纸核对，不照搬其他客户的清理名单。然后运行本机工具，输出目录必须尚不存在：

```sh
node （该脚本不随自部署版发布） \
  --source '/path/客户施工图.dwg' \
  --out-dir '.local/cad-preparation/客户-一层-v1' \
  --window '0,0,20000,15000' \
  --hide-layers '/path/需隐藏图层.json' \
  --cli '/path/cadcraft-cli'
```

示例窗口需要替换为实际坐标；没有额外隐藏层时省略 `--hide-layers`。窗口仅选取完全位于范围内的实体，不裁断跨界实体，应给整幅方案保留足够边界。CLI 路径也可由 `CADCRAFT_CLI` 提供。

脚本只读取原文件，把只读副本交给独立 CADCraft 会话，再以 `wblock` 提取窗口到衍生 DXF。清理最多 8 层嵌套图块，删除文字、尺寸、引线、栅格、非实心填充及明确隐藏的图层内容。工程几何统一到纯黑、锁定且显示的 `FMKJ_BASE`，其余图层关闭；不会强制开启实体显示，即使实体查询省略 `visible`，原本隐藏的家具变体也不会被重新显示。图纸文字和图层 JSON 均作为数据处理，不执行文档中的指令。

每次成功输出：

- `clean-base.dxf`：后续 CAD 点位桥接使用的原净底。
- `clean-base.svg`：裁去外围空纸、保留约 3% 安全边距的白底黑线矢量净图。
- `clean-base.png`：长边 3000 像素的白底净图，黑线略加粗。
- `manifest.json`：原图 SHA-256、原始实体选择窗口 `selectionWindow`、像素裁切范围 `crop`、裁切后的 `window`、净底 DXF/PNG 指纹、CAD 绑定、图片尺寸及清理计数。

布局、灯光、开关图应在同一房屋坐标系中共用裁切范围。对同一原文件、同一原始窗口的其他可见图层版本，可在上述命令中增加 `--crop-frame '/path/已确认净底/manifest.json'`；图形无法完整容纳时停止，先人工确定共同范围。不同位置的原图页先配准，不能仅因图片尺寸相同就认为可叠放。原图逐页对照的图框和留白不受净底裁切影响。此流程使用本地像素与矢量运算，不调用 AI。

会话关闭并再次验证原图指纹后才写入 `manifest.json`；没有该文件表示此次流程未完整成功。已存在的输出目录会被拒绝，调整窗口或隐藏层后使用新版本目录。单次 CAD 请求最多 55 秒，整体最多 5 分钟；SVG 超过 40 MB 时停止，先收紧范围或补充隐藏层。失败不修改原文件，也不写数据库。

先查看 PNG，核对墙体、门窗、家具、厨房与卫生间，确认没有重影或漏图，再把 PNG 用作该楼层工程底图；制作助手草稿时沿用 `manifest.cad` 及 `manifest.image` 中的尺寸，不能另行裁剪后继续使用旧绑定。这一步只准备净底，不自动确认房间、控制回路、设备安装位置或 AP/摄像头覆盖范围；相关建议继续保留待复核状态。更换底图后重新核对已摆放点位，原始图纸和已接受的旧版净底均保留。

## 导出原生点位

```sh
node scripts/cadcraft-point-map.mjs export \
  --exchange '/path/一楼-交换清单.json' \
  --base '/path/一楼-干净底图.dxf' \
  --out '/path/一楼-智能点位-01.dxf' \
  --cli '/path/cadcraft-cli'
```

也可通过环境变量 `CADCRAFT_CLI` 指定 CLI 路径；否则从 PATH 查找 `cadcraft-cli`。macOS 下载包解压后，使用其中 `cadcraft-cli` 可执行文件的完整路径。

导出前校验原净底 SHA-256；在独立进程中创建点位图块，保存并重新打开验证图块身份、位置与底图几何。输出使用新文件名，已存在的文件会被拒绝；输入原图保持不变。

当前支持工作台全部 38 个图标，包括独立的无线 AC 控制器和 PoE 交换机，并兼容 `scene-panel`、`presence` 别名。共享几何位于 `lib/point-device-symbols.mjs`：工作台 SVG、PNG 出图和 CAD 原生图块使用同一轮廓与颜色，不使用文字字符替代，也没有通用背景圆圈。图块位于 `FMKJ_POINT_MAP` 层，隐藏属性包含 `FMKJ_ID`、`FMKJ_FLOOR`、`FMKJ_DRAWING`、`FMKJ_EXCHANGE`、`FMKJ_ICON`、`FMKJ_BASESHA` 和 `POINT_CODE`。CAD handle 保存后会改变，不作为身份依据。

最终客户出图以工作台生成的 PNG 为准，它还保留点位编号、用途、施工备注、复核信息及待定位设备清单。`node scripts/generate-point-icons.mjs` 从共享几何重新生成 SVG 资产；不要单独改一份 SVG 或 CAD 图形定义。离线打包工具时须包含共享几何模块，保持 `scripts/cadcraft/` 到 `lib/` 的相对目录结构。

## 在 CADCraft 微调并回传

打开新生成的 DXF，直接移动点位图块，并另存为新 DXF。每次微调始终配套使用生成该 DXF 的同一份交换清单和原净底文件。

```sh
node scripts/cadcraft-point-map.mjs read \
  --exchange '/path/一楼-交换清单.json' \
  --base '/path/一楼-干净底图.dxf' \
  --drawing '/path/一楼-智能点位-02.dxf' \
  --out '/path/一楼-CAD回传.json' \
  --cli '/path/cadcraft-cli'
```

在工作台导入回传 JSON，查看移动清单和冲突，再应用坐标。桥接仅回传 CAD Y-up 插入坐标；工作台继续维护产品、控制关系和场景。移动后的点位需要复核，不自动变成已确认点位。

回传会拒绝以下情况：点位复制后沿用旧 ID、删除或炸开图块、未知 ID、身份属性或图块类型改变、点位换到其他图层、阵列图块、非二维点位、超出坐标窗、底图层解除锁定或隐藏、底图几何改变。新增点位请先在工作台创建，再导出新的清单；CAD 内删除点位不会直接删除工作台点位。

原净底的 SHA-256 先被核对，随后逐个比较 `FMKJ_BASE` 实体的几何和显示属性，忽略会再生成的 handle 与实体顺序；数值按 12 位有效数字统一以容纳 DXF 写回的浮点表示。因此即使曾解锁并移动底图、随后重新锁定，也会拒绝坐标回传。

## 实现边界

这是明确的文件交换流程，CADCraft 桌面程序中保存之后需要重新读取文件。图块旋转、缩放、颜色只在 CAD 图中显示，回传只更新插入位置；产品属性、场景和确认状态不写入 CAD。原生图标是类别示意符号，不代表具体型号的施工尺寸。CADCraft 仍处于早期版本，保留原始 DWG、PDF 和原净底，仅对衍生副本保存。

共享数据合同位于 `lib/point-map-cad-contract.ts`，脚本直接使用同一解析器与坐标换算，避免浏览器与桥接对 JSON 字段和 Y 方向产生不同解释。输入 JSON 不包含可执行命令、文件路径或网络地址。

## 同坐标灯光与开关对照图

先完成原图逐页核对，并从当前项目导出完整草稿。选择与工程布局同一房屋、同 WCS 窗口的灯光及开关原图页，再运行：

```sh
node （该脚本不随自部署版发布） \
  --source '/path/客户施工图.dwg' \
  --plan '/path/当前完整草稿.json' \
  --project-id '当前项目UUID' \
  --review-manifest '/path/原图对照/manifest.json' \
  --floor-id '当前楼层ID' \
  --lighting-page 'page-029' --switch-page 'page-030' \
  --out-dir '.local/cad-preparation/客户-同坐标对照-v1' \
  --cli '/path/cadcraft-cli'
```

示例页号只适用于已核对的示例项目原图，其他客户须在其原图清单中重新选择。原图指纹、单视口、冻结图层与窗口条件不符会拒绝；不同 WCS 的页面先在 CAD 配准，或在工作台使用三组建筑角点配准，不能直接复用本项目窗口。

输出 references.json、灯光 / 开关 PNG、SVG 或 PDF，以及记录来源和窗口的 manifest.json。两图使用当前工程净底的精确 CAD 窗口，长边 3000px，保留原电气文字和连线。密集 SVG 超过 40MB 时改用原生 PDF，按 CADCraft 明确打印框和窗口比例裁纸，不根据黑色像素独立紧裁。PDF 路径需 Python / pypdf、Poppler pdftoppm；可通过 CAD_REVIEW_PYTHON、PDFTOPPM 指定，缺少依赖明确失败。

在工作台“导入已配准图纸包”，核对墙体和门洞，点击“保存草稿”才写数据库。包绑定项目、楼层和工程图指纹，改过底图的项目拒绝直接套用。原 DWG、图纸包与客户图只留在忽略的本地目录；不修改报价、历史确认版或固定交付。
